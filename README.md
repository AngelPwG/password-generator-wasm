# Password Generator WebAssembly

> This is a password generator that works with handwritten WebAssembly Text (WAT), using explicit linear-memory access, and a small interface in JavaScript to use the WASM.

**I did not use Rust-to-WASM or C-to-WASM. The `.wat` file is the only source.**

<p align="center">
  ────── ⋆⋅☆⋅⋆ ──────
</p>

This password generator works as a small webapp that turns a phrase given by the user into multiple password options using WebAssembly for the generation logic.

The project was built as an excuse to work and learn WebAssembly, because it was something that I wanted to know how it works and by doing this project I learned a lot of concepts of how this language does some stuff like pointers, byte buffers, imports, exports and the data movement between JavaScript and WASM.

The browser UI is just the host, and does not have much, it has some helper functions to deliver the data ready for the WASM, and a verification for the password once it's returned from the WASM.

> **The interesting part lives in `main.wat`**

## The WebAssembly

The generator does not pass strings directly into WebAssembly.

Instead the flow is the next one:

```text
 User input
      |
      v
 ASCII normalization (because I did not want to deal with 2 bytes sized characters)
      |
      v
 TextEncoder
      |
      v
 copy bytes -> WASM linear memory
      |
      v
 pwd_gen(input_ptr, input_len, output_ptr)
      |
      v
 manual byte processing inside WebAssembly
      |
      v
 output bytes written back into linear memory
      |
      v
 TextDecoder
      |
      v
 password card
```

The generator in JavaScript calls the `pwd_gen` 3 times, so it has 3 different output regions:

```text
[4096, 4608, 5120]
```

Each call to `pwd_gen` writes its result directly into one of those regions.

## Generation

The WebAssembly module receives a pointer to the input phrase, its length, and a pointer where the generated password should be written.

In the `main.wat`, the generator can:

* randomly toggle letter case
* replace supported characters with leetspeak equivalents
* add random characters when the phrase is shorter than 12 bytes (12 letters)
* verify the resulting byte sequence
* ensure the password contains at least one uppercase letter, one lowercase letter, one number, and one symbol; if one of the classes is missing, WASM appends a randomly generated character from that class

## Randomness

The WASM module imports one function from JavaScript:

```wat
(import "env" "random_u32"
  (func $random_u32 (result i32))
)
```

The JS implementation uses the browser's Web Crypto API:

```js
function random_u32() {
  const values = new Uint32Array(1);
  crypto.getRandomValues(values);
  return values[0];
}
```

WebAssembly uses those random `u32` values for different things, like character selection, case changes, padding, and leetspeak decisions.

## WAT internals

The functions implemented directly in WebAssembly Text:

```text
$init_chars
$calc_offset
$random_char
$random_bool
$random_bef
$to_upper
$to_lower
$is_upper
$is_lower
$toggle_case
$is_leet
$to_leet
$random_upper
$random_lower
$random_number
$random_symbol
$pwd_gen
```

The module also exports its linear memory:

```wat
(memory (export "memory") 1)
```

JavaScript writes input bytes into that memory and reads the generated bytes out after `pwd_gen` returns the output length.

## Password validator

The page contains a simple password validator.

It checks for the same parameters as the validator inside WASM:

* 12 or more characters
* uppercase letters
* lowercase letters
* numbers
* symbols

> Don't ask why this is separate from the WASM, I finished the WAT and then I remembered that I needed to do that, so I did it on JS.
